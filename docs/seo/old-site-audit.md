# SEO audit: old site www.wezigns.com

Audited 2026-10-19 with read-only HTTP checks (curl). All 107 sitemap URLs were fetched over `https://www.`. I had no access to Google Search Console, Bing Webmaster Tools or any backlink or rank tool, so rankings and backlinks below are **inferred, not measured**.

## Executive summary

- The old site is a static HTML build of the **Kallyas** theme (`js/kl-*.js`) on HostGator shared Apache hosting. Almost nothing on it has changed since early 2019: 103 of 107 sitemap `lastmod` dates fall on 2019-01-31, and 103 pages show the theme date "Jan 01, 2018".
- **SEO equity is low.** I could not find the brand in web search: "wezigns Chennai" and `"wezigns.com"` returned no results for the company. There is no analytics (the GA snippet still has the placeholder `UA-XXXXX-X`), no structured data, no canonicals, no meta descriptions on inner pages, and every H1 outside portfolio items is empty (it holds only the logo image).
- **Content quality is poor.** 98 of the 100 live portfolio-item pages are Lorem Ipsum template pages. All of them carry the "AN AWESOME PROJECT" boilerplate, have the title "Portfolio Item | WEZIGNS", have no alt text on any of their 435 images, and use `href="#"` for "Live preview". Their share buttons share **kallyas-template.net**, not Wezigns. Theme leftovers appear on every page: "HOW TO SHOP / FREE shipment", "SHOWROOM HOURS Mon-Fri 9:00AM - 6:00AM", `support@website.com`, and login / create-account modals.
- **Canonical host is undefined.** `http://wezigns.com`, `http://www.wezigns.com`, `https://wezigns.com` and `https://www.wezigns.com` all return 200 with no redirects. `/` and `/index` are byte-identical, and `/about-us/` and `.html` variants also return 200. The sitemap lists `http://wezigns.com/` (http, non-www), but `og:url` uses `http://www.wezigns.com`.
- **Parking or monetisation script on error pages (important).** Every 404 on every host serves a 583-byte page that sets `_skz_pid = "9POBEX80W"` and loads `http://cdn.jsinit.directfwd.com/sk-jspark_init.php` behind a spinner. This includes `/sitemap_index.xml`, `/favicon.ico`, `/wp-admin` and `/portfolio-item-callrehabcenters` (a URL listed in the sitemap). The pattern is a domain-parking / traffic-monetisation loader that typically redirects visitors to ads. It is **not** on the real pages. The script host does not resolve in DNS today, so nothing loads right now, but the error handler is still configured. It is either a host or registrar default or an injected `ErrorDocument`, and the client should treat it as a possible compromise (details under issue C1).
- **What is worth keeping:** the domain's age (registered 2012-07-31, renews 2027-07-31 at Name.com), the brand name, the NAP for Chennai, Brisbane and Stoke-on-Trent, seven core URLs, and the social profiles. The portfolio-item URLs carry little value. 301 them anyway, because each redirect is cheap.

## Issues ranked by severity

### Critical

- **C1. Parking / monetisation loader on every 404.** On all four host variants, the 404 body is a spinner page with `_skz_pid = "9POBEX80W"` and the external script `cdn.jsinit.directfwd.com/sk-jspark_init.php`, loaded over plain http. This is the signature of a domain-parking / ad-redirect network. Crawlers and visitors that hit a broken link, including a sitemap URL, get it. The script host is NXDOMAIN today, so it currently does nothing, but if that domain comes back the redirects go live. Ask the client and HostGator to check the `.htaccess` `ErrorDocument 404` and cPanel's Error Pages, look for unknown files and FTP or cPanel users, and confirm whether Name.com or HostGator injects it. On the new host, make sure the 404 is our own page.
- **C2. No canonical host.** Four hosts plus `/index`, trailing-slash and `.html` variants all return 200, so link equity and indexing are split. The sitemap advertises a different host (`http://wezigns.com`) from the one the site uses.
- **C3. Thin, duplicate and placeholder content on 98% of indexable URLs.** About 100 portfolio pages are Lorem Ipsum with identical titles and no meta descriptions. This kind of site-wide low quality can drag down the whole domain under Google's helpful-content signals.

### High

- **H1. No tracking or measurement.** GA is a placeholder and there is no Search Console verification tag. The client may have no history to export (see the export checklist).
- **H2. Titles and headings carry no keywords.** The homepage title is "WEZIGNS | The Design Crew", with no "software", "Chennai" or service term. H1s are empty everywhere except portfolio items. Inner pages have no meta descriptions, and the homepage description is 742 characters.
- **H3. Theme leftovers and fake data.** Text like "HOW TO SHOP", "FREE shipment", "SHOWROOM HOURS 9:00AM - 6:00AM", `support@website.com`, `your-email@website.com`, `sales@yourwebsite.com`, login and register modals, the "Robix Co. / James D. Flows" client credits, and share links to kallyas-template.net and the defunct plus.google.com.
- **H4. No structured data.** There is no Organization or LocalBusiness markup for any of the three offices.

### Medium

- **M1.** All 435 portfolio images and most other images lack alt text.
- **M2.** Sitemap is stale and http-only, lists duplicates and a dead URL, uses uppercase, `%20` and underscores in URLs, and is not referenced in robots.txt.
- **M3.** robots.txt has Googlebot-only rules and an unexplained `/costin/` path.
- **M4.** Performance: about 1.5 s TTFB on shared hosting, 10–16 scripts per page, jQuery plugin stack, Freshchat and reCAPTCHA loaded everywhere, no HSTS.
- **M5.** Shared TLS certificate whose CN is another business (`*.streetfoodfactory.in`). It is valid, but it shows wezigns.com shares hosting with wezads, wedoms and wedigiting.
- **M6.** Google Maps JavaScript API key is embedded in the HTML. That is normal for browser keys, but confirm it is restricted to the site's referrers, or revoke it once the site is switched.

### Low

- **L1.** "Carrers" typo in the careers title; copy typos on About.
- **L2.** OG/Twitter tags only on the homepage, with an http image URL.
- **L3.** "Jan 01, 2018" theme date stamp on 103 pages.
- **L4.** Keywords meta (ignored by Google) stuffed with 20 phrases such as "Top 10 Website Development Company in Chennai".

## What the old site may rank for (inferred)

Without Search Console this is a guess based on titles, headings, the keywords meta and anchor text. Web search found no listing for the brand.

- **Brand:** "wezigns", "wezigns chennai", "wezigns software", "wezigns the design crew". These are the most likely real rankings, and brand searches are where the equity is.
- **Local service terms (weak):** "web design company Chennai", "website development company Virugambakkam / Arcot Road", "ecommerce development Chennai", "logo design Chennai", "digital marketing Chennai". These come from the keywords meta and the `/our-services` text. They are highly competitive and unlikely to rank with this content.
- **Portfolio client names:** "Elite Care Recruitments", "CKCar rental", "Rajkumaran builders" and similar. Pages might show for a client's name plus "website", but their content is placeholder text.
- **Google Business Profile:** the Maps embed points to a place named "WEZIGNS" (CID `0x2c10b00f9a8a4bbe`). The Maps listing probably drives more local visibility than the website does, so keep it and update its website link.

## Recommended redirect strategy (107 sitemap URLs plus variants)

1. **Choose one canonical origin**, for example `https://www.wezigns.com`. 301 the other three host variants (http, non-www) to it at the edge, preserving the path, in a single hop.
2. **Core pages**, one-to-one 301:
   - `/index`, `/index.html` → `/`
   - `/about-us` → `/about` (or keep `/about-us`)
   - `/our-services` → the new systems overview (currently `/our-services`, so it may need no redirect)
   - `/portfolio` → the new work section or page
   - `/careers` → a careers page if one exists, otherwise `/about`
   - `/contact-us` → `/contact`
   - Also handle the trailing-slash and `.html` variants of each.
3. **Portfolio items (100 URLs):** 301 any item that has a matching real case study on the new site to that page. 301 every other `/portfolio-item-*` to the work section. Do not send them all to the homepage, because Google treats mass homepage redirects as soft 404s. A single wildcard rule (`/portfolio-item-:slug` → `/#work` or `/work`) is enough, with specific rules placed before it. Match case-insensitively and accept `%20`.
4. **Dead URL** `portfolio-item-callrehabcenters`: let the wildcard catch it.
5. **Everything else** gets a clean 404 page with a real 404 status, never the parking script.
6. **After launch:** publish a new https sitemap, add a `Sitemap:` line to robots.txt, set canonicals and Organization/LocalBusiness JSON-LD on every page, submit the new sitemap in Search Console and Bing, and keep the 301s for at least 12 months. Do not use the Change of Address tool, since the domain stays the same.

## Export from Search Console and Bing before switching

I could not reach these, so ask the client to export them before DNS cutover:

- **Search Console (each property: the domain property and any `http://`, `https://`, www and non-www URL-prefix properties):**
  - Performance → last 16 months → Queries and Pages tabs (CSV), plus Countries
  - Links → Top linking sites, Top linked pages (external) and internal links
  - Pages (indexing) → indexed and not-indexed lists
  - Sitemaps
  - Manual actions and Security issues. This is especially important given the parking script.
- **Bing Webmaster Tools:** Search Performance (queries and pages), Backlinks, and Site Explorer.
- **Google Business Profile:** website link, categories, review count, and Insights (searches and calls).
- **If there is no verified property:** verify the domain property by DNS now. Data starts accruing from verification, and even a few weeks of baseline before the switch helps.
- **Optional:** a free Ahrefs Webmaster Tools or Semrush backlink snapshot after verification, to find the old URLs that external sites link to and give each one a specific redirect.
